# Proveedores de doramas — evaluación del 24-11-2026

## Integrada

### SeriesBL (`seriesbl.net`, clave `seriesbl`)

```
/?s=<título> → /series/<slug> → /episode/<slug>-<T>x<E>
→ <li dooplay_player_option data-post data-nume data-type>
→ POST /wp-admin/admin-ajax.php (doo_player_ajax)
→ pkaa.top/embed.php → Byse → HLS
```

- La ficha de «ABO Desire» declara 2025 y el enlace `/episode/abo-desire-1x1/`.
- El AJAX devolvió `pkaa.top/embed.php`; su HTML publica
  `bysebuho.com/e/…`, que el extractor `byse` del addon resolvió a un HLS con
  manifiesto válido (HTTP 200).
- El sitio es de catálogo BL (boys love): se etiqueta «Subtitulado» porque sus
  fichas declaran «Sub Español» y no doblaje.

## Descartadas

| Web | Motivo |
|---|---|
| `doramasflix.in`, `doramasflix.io`, `doramasmp4.io`, `doramasia.com` | Misma plataforma (`user-api.seriesapi.co`); su GraphQL responde **403 con challenge** al runner. Los espejos no aportan catálogo propio. |
| `www.doramasyt.com` | Los botones `data-player` sí enlazan a Byse con HLS al leer con `fetch` directo, pero el cliente del addon (`lib/http.js`) recibe `cf-mitigated: challenge` en `/buscar`: se descarta sin intentar saltar el reto. |
| `doramaslat.com` | Ficha y episodios correctos, pero el único embed del episodio controlado es `ok.ru` (sin extractor) y el servidor alternativo respondió 500. |
| `doramedplay.net` | HTTP 403 desde el runner. |
| `kdramasplay.com`, `pandrama.tv`, `pandrama.io`, `pandrama.com`, `doramasvip.org` | Error de red/TLS en el runner; no se pudo ni leer la portada. |
| `yandispoiler.net` | HTTP 503. |
| `tudorama.com` | Portada 200, pero sin fichas para la consulta de control. |
| `doramasub.com` | HTTP 429. |
| `doramasqueen.com` | Buscador devolvió una página vacía. |
| `doramasflix.co`, `animeonline.ninja` | 403 / fuera de esta fase (no son webs de doramas). |

Estos dominios no entran en el registro. Un HTTP 200 con fichas no basta: hacía
falta un HLS/MP4 directo con idioma declarado y acceso estable desde servidor.
